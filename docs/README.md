# Техническая документация LexGuard

Добро пожаловать в раздел документации проекта **LexGuard** — интеллектуальной системы автоматизированного юридического анализа контрактов.

Этот раздел содержит актуальную информацию о внутренней архитектуре проекта, процессах машинного обучения, потоках данных и выявленных рисках/краевых случаях. Документация предназначена для разработчиков, желающих восстановить контекст или продолжить развитие системы.

## Быстрый старт

```bash
# 1. Настроить модель (локально: gemma2:2b, сервер: llama3.1:8b)
echo "LLM_MODEL=gemma2:2b" > .env

# 2. Запустить инфраструктуру
docker compose up -d

# 3. Дождаться загрузки модели
docker logs -f lexguard-ollama-init

# 4. Накатить миграции
docker exec lexguard-backend alembic upgrade head

# 5. Открыть UI
open http://localhost:3000
```

## Поддерживаемые модели

| Модель | VRAM | Скорость | Качество | Рекомендация |
|--------|------|----------|----------|--------------|
| `gemma2:2b` | 4GB | Быстро | Базовое | Локальная разработка |
| `gemma3:4b` | 8GB | Средне | Хорошее | Fallback на сервере |
| `llama3.1:8b` | 16GB | Медленно | Отличное | Production |
| `gemma3:12b` | 24GB | Медленно | Лучшее | Production (с мощным GPU) |

## Конфигурация через переменные окружения

| Переменная | Описание | По умолчанию |
|------------|----------|--------------|
| `LLM_MODEL` | Модель Ollama | `gemma2:2b` |
| `OLLAMA_URL` | URL Ollama API | `http://ollama:11434` |
| `LLM_REQUEST_TIMEOUT` | Таймаут запроса (сек) | `300` |
| `LLM_HEARTBEAT_TIMEOUT` | Таймаут heartbeat (сек) | `600` |
| `MIN_RELEVANCE_SCORE` | Порог RAG (0.0-1.0) | `0.50` |
| `LLM_MAX_WORKERS` | Параллельные workers | `2` |

Полный список см. в `backend/.env.example`.
